# 模拟设备与调度使用说明

此功能只用于内置运动学模拟，设备不会连接 PLC、门控、梯控或充电桩。创建 `device` 任务时只分配模拟机器人。设备模型和当前占用保存在 Core 数据库中，设备更新通过 WebSocket `device` 消息发布，完整世界快照包含 `devices`。可在地图编辑器选择地面路线，在属性面板添加模拟门，也可通过 `/docs` 或下列 REST 接口操作。

## 建立设备

先在已有地图中准备有效的地面站点。示例使用 `warehouse_demo` 的已有站点，实际请按照地图确定入口、出口和室内点，确认路径可达：

```http
POST /api/v1/devices
Content-Type: application/json

{"id":"door_1","name":"模拟门","type":"door","map_id":"warehouse_demo","entry":"NA1","exit":"NA2","lane_id":"LN1","duration_s":0.5}
```

门设置 `lane_id` 后即与路线绑定，普通导航、配送等任务沿该路线通行时会自动申请设备并模拟开门；入口和出口必须是该路线两端。不设置 `lane_id` 的旧设备仍只供调试任务使用。`type` 支持 `door`、`air_shower`、`terminal`、`bin`、`charger`、`lift`。风淋室还必须设置 `inside`；库位可以设置初始 `occupied`。入口、室内、出口必须属于同一地图。`duration_s` 是每个模拟设备动作的耗时，单位秒。电梯可登记，跨楼层任务当前会明确拒绝。

使用 `GET /api/v1/devices` 或 `GET /api/v1/devices/door_1` 查看状态，用 `DELETE /api/v1/devices/door_1` 删除空闲且没有未结束任务引用的设备。

## 派发任务

```http
POST /api/v1/tasks
Content-Type: application/json

{"type":"device","params":{"device_id":"door_1","direction":"forward"},"requirements":{"robot_id":"ugv_01"}}
```

这是保留的调试接口，正常业务任务无需创建此类任务。系统先导航至入口，再独占模拟设备、执行模拟动作，门和风淋室继续导航至出口并释放设备；结果通过现有任务 API 查看。`direction` 可选 `forward` 或 `reverse`，用于门和风淋室；风淋室正向模拟风淋、反向只模拟双门通行。库位任务指定 `operation` 为 `pickup` 或 `dropoff`，成功后改变模拟占货状态，不满足初始货位状态则失败。终端模拟握手；充电桩在入口执行模拟机器人的原生充电动作直至电量阈值。任务可用 `/api/v1/tasks/validate` 预览。

同一设备同时只允许一个设备任务占用。设备任务等待设备时可取消；已取得设备后取消、故障、异常或者 Core 重启，设备保持占用并进入 `recovery_required`。在确认模拟机器人位置并处理原任务后，调用 `POST /api/v1/devices/{id}/recover` 清除模拟占用；活动任务不能被恢复接口清除。`POST /api/v1/devices/{id}/fault`，请求 `{"fault":true}`，可模拟故障，`false` 清除故障。故障中的设备不会接受新的设备任务。

## 当前边界

- 已绑定路线的模拟门由普通任务自动触发，双向通行均适用；导航器在入口等待开门，再下发通过该路线的移动指令；到达另一端后模拟关门，关门完成才释放设备。事件面板记录开门请求、开门成功、关门请求和关门成功。电梯、风淋室及工位设备还没有自动路线或业务步骤绑定。设备互斥不是物理空间占用的完整模型；目前按模拟机器人抵达路线另一端释放，未检查真实车尾。
- 状态与动作是定时模拟，不包含 PLC 信号、传感器、防夹、风淋互锁、设备动作实时反馈或真实货物。设备故障在当前导航段完成后检查，无法实现实时硬件联锁。
- 风淋、门通过依赖所选点之间的导航结果，尚未校验指定车道或车尾完全离开；电梯无跨楼层路线、切图与定位；`terminal` 没有实际产线信号；`charger` 没有 SRC800 通信。
- 会话持久化用于保留占用，不能恢复设备动作；重启后活动任务按现有机制取消，需手工恢复模拟设备。以上功能未在真机或物理仿真中验证，不可用于真实设备控制。

绑定或移除路线设备时，地图上不能有未完成任务或活动交通计划；需要先移除设备才能删除关联路线或站点。模拟门故障时等待或中断并保留占用，恢复由操作员在 `/docs` 中调用设备恢复接口。

模拟门分别记录占用状态和 `door_status`（`closed`、`opening`、`open`、`closing`、`unknown`）。路线任务在请求开关门之前记录状态检查：已打开或已关闭时跳过对应请求；状态未知或正在动作时，任务在门前失败且不会发出开门请求；此时可设置模拟门状态后重新派发任务。通行中或动作中断时保留占用，等待人工恢复。模拟动作中断时门状态变为未知。新建模拟门初始为关闭；旧版本保存的门没有门状态，升级后标记为未知，可在地图编辑器选中对应路线、在设备空闲时设置模拟门状态，或调用 `POST /api/v1/devices/{id}/simulated-status`，请求 `{"status":"closed"}`。如果有中断的占用，先确认模拟现场，在地图编辑器点击“恢复模拟设备”（或调用恢复接口），再设置状态。此状态是模拟值，不代表真实门磁反馈。

## 模拟充电设备

在地图编辑器选中已有的充电站点或停机坪，填写设备 ID、名称并点击“添加模拟充电设备”。每个站点只能绑定一台设备；原有站点不会自动创建充电设备，需逐个配置。调度主页选中该站点可查看设备状态、占用任务、机器人和阶段，也可模拟故障或恢复。

普通充电任务和低电量自动充电使用同一流程：先预约可达、同图层的模拟设备，导航到站点，执行模拟对接，确认机器人进入充电状态，到目标电量后停止充电并解除对接。充电完成后机器人仍停在站点，设备持续占用，直到机器人离开站点一定距离；没有绑定设备的充电站点不会执行模拟充电。故障或中途取消可能保留占用并要求人工恢复；恢复前应确认模拟机器人已离开。系统不会自动创建退出路线，需派发后续任务让机器人离开。

充电桩兼容性目前仅检查地图和地面/空中图层；机器人外形、充电接口及实际协议匹配还未实现。对接与解除对接是模拟动作，并不执行真实对接或读取物理设备反馈。已运行的 Core 必须重启才能加载此后端变更。

在调度主页选中绑定了模拟充电设备的站点后，可选择机器人点击“充电”，创建前往该站点的充电任务；设备已有进行中的充电任务时可点击“取消充电”。取消会停止模拟充电，设备可能保留占用并需要确认恢复。取消后该机器人不会立即自动重新充电；再次手动发起充电或重启 Core 后恢复自动充电策略。
