# 三维调度视图

在“调度”页面的地图上方选择 **3D**，可查看当前选中地图；选择 **2D** 返回二维视图。默认使用二维视图。三维视图直接读取 Nayantra Core 的地图和实时机器人状态，不启动另一套仿真。

- 鼠标左键拖动旋转、右键拖动平移、滚轮缩放；右下角的按钮也可缩放或重置为正面斜俯视全图（快捷键 F）。三维背景跟随界面深色或浅色主题。鼠标指向地面时显示地图坐标，网格开启时显示网格间距。透视视图中的比例随位置变化，因此不使用二维固定比例尺。
- 点击机器人或路径点查看原有详情；选择机器人时按住 Shift、Ctrl 或 Command 可多选。机器人颜色表示状态，点击左下角“三维图例”查看颜色含义。四种机器人使用可区分的简化外形。
- 机器人充电时显示蓝色能量光环、粒子和已报告的电量；执行动作、移动、等待、暂停和故障分别显示对应状态光环。每台机器人的规划路径、终点和名称边框使用对应的路线颜色，机器人本身的颜色仍表示状态。移动机器人的规划路径上会出现沿行进方向流动的光带；无人机及腿部模型在报告运动时会有简化动作。状态文字来自 Core，路径流光和动作仅作视觉提示，不表示额外的设备遥测。断线时动画停止并保留最后状态；系统开启“减少动态效果”时使用静态提示。
- 图层按钮可控制底图、网格、墙体与障碍物、区域、地面和空中通道、路径点、名称、机器人、规划路径、轨迹、交通预约及冲突等待。区域名称和部分路径点名称受“标签”开关控制；交叉点默认不显示名称，选中时显示。
- 地面通道用实线显示；空中通道、关闭通道使用虚线，关闭通道显示为红色。单向通道显示方向箭头。空中通道使用地图定义的高度，路径点使用其 z 坐标。
- 当 Core 有对应数据时，三维视图显示预约通道或节点、等待关系和冲突位置。轨迹只包含当前前端会话收到的有限位置记录，不是持久历史。
- 连接断开时，画面保留最后收到的位置并显示提示。重新连接后 Core 会发送完整快照，画面自动恢复。
- “前往”操作需要选择二维地图上的路径点；启用该操作会切回二维视图。地图编辑也在二维界面进行。

墙体和障碍物由地图几何生成，默认高度分别为 1.3 米和 1.8 米，仅用于显示；它们不改变路线规划或碰撞规则。地图坐标的 x、y 对应三维场景的 x、-z，机器人高度使用状态中的 z。底图根据原点、旋转和分辨率放置。

机器人规划路径由 Core 提供的二维点组成，不包含每个点的高度；空中机器人的路径以其最新报告的高度绘制，仅用于观察，不能据此判断实际三维飞行轨迹。轨迹同样只有二维位置，显示在地面。简化机器人外形是视觉示意；模型渲染与位姿、状态、选择逻辑分开，未来硬件资产模块可替换外形。当前没有模型上传、资产关联或模型加载功能。内置模拟是运动学模拟，三维显示不代表物理仿真或真机验证。

## 开发说明

调度页面通过 `web/src/pages/Operations.tsx` 按需加载三维视图，并复用 `useWorld` 中来自 Core WebSocket 的地图、机器人、交通及连接状态。`Map3D.tsx` 负责坐标转换、位姿平滑、视角和图层装配；`SceneLayers3D.tsx` 绘制地图与交通图层；`RobotModels3D.tsx` 只负责默认模型外形。后续接入硬件资产模型时，应继续由 Core 状态驱动位姿和状态，并在模型展示层处理模型的比例、原点及朝向。

`robotVisualState.ts` 统一故障、离线、充电等视觉状态的优先级；`RobotEffects3D.tsx` 和 `FlowingPath3D.tsx` 只生成显示效果，不参与调度。路线颜色由 `routeColors.ts` 按机器人分配，在当前三维视图会话中保留；刷新页面或重新进入三维视图后，会根据当前机器人列表重新分配。机器人注册列表变化时，已分配的颜色在当前会话内不变。

修改后可运行 `cd web && npm run build`、`npm run test:3d` 和 `npm run test:i18n`。实际设备模型、物理碰撞和真机运行需要分别验证。
